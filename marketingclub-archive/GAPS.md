# Gaps — what is not in this archive

Everything the A.I. Marketing Club exposes to this account is archived. This
file records the exceptions, so a future reader knows the difference between
"missing" and "never available".

Account used: `AI Marketing Club Basic Access` (`memberstack: ai marketing club`).

## 1. Platinum Passport tab — gated, not visible to this account

`/api/content-access-rules` returns exactly one rule:

```json
{"id": 52, "tabId": "platinum-passport", "tabLabel": "Platinum Passport",
 "allowedValues": ["Platinum Passport"]}
```

This account does not hold the `Platinum Passport` tag, so the tab and whatever
sits behind it never reach the client. Nothing was blocked or worked around —
the content is simply not served. A Platinum member re-running `.tools/` would
pick it up automatically; no code change needed.

## 2. Three endpoints are empty for this tier

| Endpoint | Response |
|---|---|
| `/api/bonus` | `[]` |
| `/api/events` | `[]` |
| `/api/valuebombs` | `[]` |

They are wired up in the SPA but carry no rows for this account. `/api/addevent-events`
(the calendar feed) does return 2 items, archived under `05-events/`.

## 3. 58 hub videos are embed-only — no downloadable file exists

Of 181 hub items, 123 resolve to a real file URL via
`/api/hub-agent/products/<slug>/items/<id>/download-url`:

| Item type | Count | Download URL |
|---|---|---|
| document | 68 | resolved |
| audio | 55 | resolved |
| video | 58 | none — endpoint returns no file |

The 58 videos are streamed through Video Vault / Wistia and have no file object
behind them. Their embed URLs are recorded in each lesson's Markdown and in
`raw-json/videovault-share-ids.json`, so playback still works from the archive;
only the raw MP4 is unavailable. Same for the 19 live classes — video is an
embed, but every one of them has a full transcript committed here.

## 4. 8 checklist PDFs are dead links in the club itself

Section `02-main-content/01-business-growth-checklists/` links 10 PDFs on
`members.buildprofitablebusiness.com`, an old Eben Pagan membership domain that
no longer resolves (NXDOMAIN, not a 404 — the host is gone). The Wayback Machine
has no snapshot of any of the 10.

Two of the ten titles survive because the same PDFs are also served live from
the Webflow CDN under section `02-15-point-video-sales-letter-formula`, and those
copies **are** committed:

- `Finding-a-Profitable-Niche.pdf`
- `How-To-Create-Your-Customer-Avatar-Step-By-Step.pdf`

The remaining 8 are unrecoverable from any source reachable today:

- 7 Steps To A Successful Information Product
- How To Create Magnetic Names For Your Product, Services And Ideas
- 7 Winning Headline Formulas
- The Key Elements Of Optimized Optin Pages
- The Proven Online Sales Letter Checklist
- How To Write Persuasive Copy That Sells
- Creating Stories That Sell
- The Effective Email Template

Each session's Markdown still carries the title, description, and the original
(dead) URL for provenance. Recovering them needs the club to re-host the files.

## 5. Audio and video are linked, not committed

64 media references (55 hub audio + 9 main-content session audio) are over 1 GB
and exceed what belongs in git. They are gitignored, not lost:

```bash
python3 .tools/fetch_files.py --media
```

pulls them next to the lesson that references them. Every URL lives in
`raw-json/hub-download-urls.json` and `raw-json/main-content.json`.

## 6. Member contact details are deliberately stripped

`/api/members` returns 975 member records including email addresses. The
committed `04-members/directory.md` and `04-members/members.json` drop every
contact field (email, phone, address, Stripe/Memberstack ids, tokens, IPs). This
is a privacy choice, not a technical limit — see `REDACT` in `.tools/build_all.py`.
`raw-json/members.json` holds the verbatim payload and is gitignored for the
same reason. So are `raw-json/auth-user.json` and `raw-json/members-me.json` —
this account's own profile, which carries the login email. All three are
regenerated by `.tools/fetch_all.py`, so nothing in the pipeline depends on them
being committed.

## 7. Admin surfaces are out of scope

This is a member account (`isAdmin: false`). Admin/authoring endpoints were not
probed and are not part of this archive.
